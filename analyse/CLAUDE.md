### Subtilité 1 : décision sur le rachat du mobilier home staging

**Situation :** le mobilier installé par le prestataire de home staging (Anaïs, prestataire externe) est actuellement loué pour 980 €/mois. Le prestataire propose un rachat global pour 4 362,80 € (le mobilier total a une valeur de 10 242,80 €, dont 5 880 € ont déjà été payés via la location).

**Analyse :**
- Coût mensuel de location : 980 €
- Coût du rachat : 4 362,80 €
- Point mort : 4 362,80 / 980 = **4,5 mois**
- Si le bien reste en exploitation/portage plus de 4,5 mois, le rachat est financièrement avantageux

**Avantages annexes du rachat :**
- Mobilier devient propriété de la SAS, peut être inclus dans la vente du bien meublé ou revendu séparément

### Subtilité 2 : régime fiscal MDB et TVA sur marge

**Engagement de revendre** souscrit dans l'acte d'acquisition : 5 ans à compter du 30 avril 2024, soit deadline au **30 avril 2029** (prorogeable annuellement).

Bénéfice fiscal obtenu : droits de mutation à taux réduit (taxe départementale 0,70 % au lieu du taux normal ~4,5 %), soit une économie de ~12 600 € sur les droits.

**Conséquence en cas de non-revente avant le 30/04/2029 :** perte rétroactive du bénéfice du taux réduit, à rembourser à l'administration fiscale.

**TVA sur marge à la revente** (régime MDB) : la TVA se calcule sur la marge brute (prix de vente − prix d'achat − frais d'acquisition), pas sur le prix total. **Important : les travaux ne réduisent pas la marge taxable** (particularité MDB qui surprend souvent).

## Spécifications techniques pour le rendu HTML

### Format de sortie attendu

Un **fichier HTML autonome unique** (`rapport-la-releve-hyeres.html`) avec :
- Structure HTML5 sémantique propre (`<main>`, `<section>`, `<article>`, `<header>`, `<nav>`, etc.)
- **Aucun CSS inline ni styles écrits dans le HTML** (utilisation uniquement de classes)
- Classes CSS sémantiques en BEM-style pour permettre l'intégration avec un CSS externe existant
- Aucune dépendance externe (pas de CDN, pas de polices Google, pas de JS framework)
- Compatible mobile (responsive via classes utilitaires uniquement, le CSS responsive sera ajouté par l'utilisateur dans son CSS commun)
- Imprimable proprement en PDF depuis le navigateur

### Convention de nommage des classes CSS

Utiliser un système BEM (Block Element Modifier) cohérent. Exemples :
- `.report` : conteneur principal
- `.report__header` : en-tête du rapport
- `.report__nav` : sommaire navigable
- `.report__section` : section thématique
- `.report__section-title` : titre de section
- `.report__section-content` : contenu de section
- `.data-table` : tableaux de données
- `.data-table__header` : en-tête de tableau
- `.data-table__row` : ligne de tableau
- `.data-table__cell` : cellule
- `.data-table__cell--number` : cellule numérique (alignée à droite)
- `.data-table__cell--total` : cellule de total (en gras)
- `.highlight-box` : encadré pour mettre en avant une information clé
- `.highlight-box--neutral` : encadré informatif neutre
- `.highlight-box--warning` : encadré d'alerte
- `.flag` : marqueur "à confirmer" / "hypothèse à valider"
- `.scenario-card` : carte présentant un scénario
- `.scenario-card__title` : titre du scénario
- `.scenario-card__metrics` : métriques clés du scénario
- `.comparison-table` : tableau comparatif des scénarios

### Structure du document

Le HTML doit s'organiser ainsi (dans cet ordre) :

1. **`<header>` du rapport** : titre principal "Opération immobilière 3 rue Fenouillet, Hyères — Analyse de situation", sous-titre "Document interne d'aide à la décision pour les associés de La Relève Hyères", date de génération
2. **`<nav>` sommaire navigable** : liste des sections avec ancres internes (`<a href="#section-id">`)
3. **Section 1 — Résumé exécutif** : 3-4 paragraphes courts présentant la situation actuelle, le coût net mensuel de portage, l'offre à arbitrer et les principaux scénarios disponibles. Pas de recommandation, juste un état des lieux factuel.
4. **Section 2 — Contexte de l'opération** : présentation du bien, de la société porteuse, du calendrier de l'opération depuis avril 2024
5. **Section 3 — Coût de revient** : tableau détaillé acquisition + frais notaire + travaux, avec distinction HT/TTC et note sur la récupération TVA
6. **Section 4 — Structure de financement et coût de la dette** : détail Baltis (contrat initial + régime de prorogation actuel), fonds propres associés, encadré sur l'effet temps des coupons mensuels avec tableau de cumul selon date de sortie
7. **Section 5 — Charges récurrentes** : tableau annuel des charges (Baltis, taxe foncière, énergies, assurance, location meubles, copro), avec encadré sur la subtilité du rachat du mobilier (point mort + tableau d'économies selon durée)
8. **Section 6 — Revenus location courte durée** : tableau mensuel consolidé Airbnb + Booking, observations sur la saisonnalité, mention de la perte de revenus liée aux annulations Booking
9. **Section 7 — Coût net de portage** : calcul du coût net mensuel et annuel, avec et sans rachat des meubles
10. **Section 8 — Historique de commercialisation** : tableau des 3 offres reçues, lecture du signal marché
11. **Section 9 — Contraintes temporelles** : engagement MDB (30/04/2029), hypothèque Baltis (25/01/2028), échéance Baltis renégociée (septembre 2026), AG copro (mai-juin 2026)
12. **Section 10 — Trois scénarios de sortie chiffrés** : présentation détaillée de chaque scénario (A, B1, B2, C1, C2) avec son calcul cash complet
13. **Section 11 — Tableau comparatif des scénarios** : synthèse visuelle permettant de comparer les 5 scénarios sur les mêmes métriques (prix, délai, coût portage, solde final)
14. **Section 12 — Zones d'incertitude** : liste des 10 points à clarifier
15. **Section 13 — Glossaire et notes méthodologiques** : définitions courtes (MDB, TVA sur marge, in fine, CCA, etc.), sources des chiffres, hypothèses retenues

### Règles de présentation des chiffres

- Format français : espace comme séparateur de milliers, virgule comme séparateur décimal (ex: "332 000 €", "11 054,22 €")
- Symbole € après le chiffre avec espace insécable (`&nbsp;€`)
- Pourcentages avec espace : "11&nbsp;%"
- Dates au format français : "30 avril 2024" ou "30/04/2024" selon le contexte
- Montants négatifs entre parenthèses ou précédés d'un signe moins explicite
- Cellules numériques alignées à droite via classe CSS

### Ton et style rédactionnel

- **Neutre, factuel, non prescriptif** : pas de "vous devriez", "il faut", "nous recommandons"
- Utiliser "l'opération", "les associés", "la SAS" plutôt que des pronoms personnels
- Phrases courtes, vocabulaire technique précis mais accessible
- Pas d'emojis, pas de tournures familières
- Chaque chiffre cité dans le texte doit être traçable à un tableau ou une source clairement identifiée
- Pour les éléments incertains, utiliser systématiquement la classe `.flag` avec mention "(à confirmer)" ou "(hypothèse de travail)"
- Pas de superlatifs : éviter "extrêmement", "énormément", "très" — préférer des chiffres
- Pas de "malheureusement", "heureusement" ou autre marqueur émotionnel

### Accessibilité et impression

- Hiérarchie de titres respectée (`<h1>` unique pour le titre du rapport, `<h2>` pour les sections, `<h3>` pour les sous-sections)
- Tableaux avec `<thead>` et `<tbody>` distincts
- Attributs `scope="col"` et `scope="row"` sur les en-têtes de tableau
- Liens du sommaire avec `aria-label` explicite si nécessaire
- Aucun élément crucial uniquement véhiculé par la couleur

## Livrable final

Le fichier `rapport-la-releve-hyeres.html` doit être :
- Un seul fichier autonome
- Sans CSS interne (uniquement les classes BEM documentées ci-dessus)
- Valide HTML5
- Lisible tel quel dans un navigateur même sans CSS appliqué (la structure sémantique doit suffire à la compréhension)
- Prêt à être intégré dans un environnement web où le CSS commun sera appliqué

À côté du fichier HTML, générer également un fichier `CLASSES.md` listant l'ensemble des classes CSS utilisées avec une description courte de leur usage, pour permettre à l'utilisateur de créer son CSS personnalisé ou d'adapter son CSS existant.
